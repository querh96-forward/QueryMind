本文记录SQL执行控制阶段的测试方法、实测结果与失败案例。

## 已实现

- 工具错误分类：表结构/字段、SQL语法、查询超时、数据库连接和权限拒绝；返回可重试标记及修复建议。
- 调用前按 JSON Schema 校验参数；权限错误直接停止，SQL累计失败超限后停止。
- 完善模型循环、工具次数、重复调用、Token与运行时限控制；被跳过的工具请求仍有完整响应和审计记录。
- 修正首次SQL成功率被后续重试覆盖；成功查看结构不会掩盖先前SQL失败；查看结构或指标后保留SQL表格。
- SQL AST 拦截多语句、写操作和非业务对象；实际执行限制最多200行。
- 新增24题评测集、顺序/数值容差判定、超时区分、逐题报告和版本指纹。
- 补齐 `.env.example`、运行配置与项目文档，调整界面措辞，明确执行检查不等同于答案正确。

## 保留的失败案例

`portfolio_21` 要求查询2000年及以后的订单，标准结果为空。

1. 模型先正确执行日期筛选，返回0行。
2. 随后追加最早/最晚日期与订单总数的诊断查询，返回1行。
3. 现有展示逻辑使用最近一次SQL结果，导致最终表格成为诊断统计，判为失败。

该样本保留在报告中。后续需要增加多次查询的结果选择与证据绑定，不能简单把所有空结果强行判为正确。

恢复、重复调用、权限终止等路径已通过自动化故障测试验证；这24题没有自然产生SQL执行失败，因此不能据此宣称真实恢复成功率。

## 运行与复测

在项目目录执行：

```bash
docker compose up -d --build
docker compose exec -T api python -m pytest -q tests
docker compose exec -T api python evals/run_eval.py --require-real --output /app/evals/reports/retest-real.json
docker compose cp api:/app/evals/reports/retest-real.json ./evals/reports/retest-real.json
```

应用地址： http://127.0.0.1:6006 。再次评测会调用真实模型并产生相应用量。没有密钥或处于Mock模式时，`--require-real` 会拒绝运行。

保留题结果不用于本轮提示词或代码调参；若未来根据这些题优化，应更换新的保留题。
